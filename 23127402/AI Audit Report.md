## 9. Conclusion — When should AI be used (or not)?

AI (DeepSeek) demonstrated strong capability in generating structurally complete test-case tables following EP and BVA methodologies, consistently producing well-formatted Markdown output suitable for direct inclusion in reports. It excelled at template-driven tasks such as converting bug data into GitHub Issues and creating reusable skill files — tasks where the output structure is well-defined and the input data is explicit.

However, the audit reveals three recurrent failure modes. **First, AI systematically under-generates**: when asked to produce multiple bugs in a single session, it produced only 2 of 8 (75% omission rate). This is not a comprehension failure but a generation-completeness failure — the AI treated "find bugs" as a sampling task rather than an exhaustive enumeration. **Second, AI struggles with implicit requirements**: UI elements not explicitly listed in the input-variable analysis (Back to Login button, Confirm Password field) were consistently overlooked, requiring human review to catch. **Third, AI makes domain assumptions**: it generated 'Thời trang' as a product category because that fits generic e-commerce training data, not because it verified against the actual SUT.

The 30% incompleteness rate in artifacts directly translates to a requirement for **structured prompt engineering** — not just better AI, but better prompting methodology. The most effective pattern observed in this audit was the iterative refine cycle: AI generates a first draft → human identifies gaps → AI fills specific narrow gaps in subsequent focused prompts. This pattern, applied across 15 commits over 13 days, ultimately produced a comprehensive test suite covering 4 features with 16 documented bugs.

**Final assessment:** AI should be used as a **first-draft generator and formatting engine**, but must never be the sole source of truth for completeness. The human tester must always perform a requirements-coverage walkthrough against the specification document to catch AI omissions. For HW#03 and beyond, the recommended workflow is: (1) prepare a context file with SUT data and mappings, (2) use focused single-output prompts, (3) run a coverage checklist against specifications, and (4) close gaps with targeted follow-up prompts.
